and undo. GitHub receives a public export through the bridge in
[`SELF_HOSTING.md`](../SELF_HOSTING.md). The existing published README and licenses
were preserved by a native TIG merge.

## Real-source comparison

```
python bench/self_host_compare.py --baseline .git/tig-bootstrap/tig-before-status.exe --runs 15 --json bench/self-hosting-2026-10-17.json
```

The fixture is the **163-file public TIG source tree**, not generated files.
The exported source commit and executable SHA-256 hashes are recorded in the
[raw samples](self-hosting-2026-10-17.json). The baseline executable was retained
before this feature; a fresh checkout does not contain that ignored executable.

Preparation is outside the timings. Git uses a shared clone of the exported
history; each TIG binary starts from an independent copy of the same files and
an initialized workspace. The stat-cache racy window expires before warming
status. Tool order alternates each round. Every sample starts a real CLI process;
stdout/stderr are discarded consistently. Edited samples append the same bytes
to `README.md` independently for each tool. Record samples run Git `commit -qam`
or TIG `new -m`, including snapshotting the edit. No other benchmark driver or
build/test run was active during measurement.

Median milliseconds, 15 samples per cell:

| Operation | Git | Previous TIG | Current TIG | Current / Git | TIG `--short` |
|---|---:|---:|---:|---:|---:|
| Clean status | 50.63 | 22.15 | 21.49 | 0.42x | 21.34 |
| Edited status | 61.64 | 37.94 | 33.73 | 0.55x | 38.67 |
| Record change | 123.83 | 60.37 | 53.11 | 0.43x | 55.29* |

\* The short-output fixture uses the same ordinary `new` command for recording;
there is no short-output recording feature. This is an independent sample of the
same binary and command.

This is one Windows desktop sample on a small real repository. Antivirus and
normal background services remained active. TIG status also records edits,
whereas Git status inspects them. These numbers show wins for these measured
workflows, not universal superiority or a causal speedup from the output flag.
In particular, short edited status measured slower than ordinary current status.
The previous [10k-file baseline](RESULTS.md) includes an edited-status loss to Git;
that larger workload remains a performance target.
